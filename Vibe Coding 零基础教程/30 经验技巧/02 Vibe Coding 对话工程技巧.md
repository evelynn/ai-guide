# Vibe Coding 대화 엔지니어링 기법

> 반복적 대화의 예술



안녕하세요, 저는 유피입니다.

이전 글에서 Vibe Coding의 5가지 핵심 심법에 대해 이야기했습니다. 오늘은 그 중 가장 중요한 기술 중 하나인 AI와 효율적으로 대화하는 방법에 대해 심도 있게 탐구하겠습니다.

많은 학생들이 AI를 사용할 때 마법 버튼처럼 생각합니다: 한 문장을 입력하고 완벽한 답변을 기대합니다.

하지만 현실은 종종 AI가 제공하는 결과가 틀리거나 충분히 좋지 않습니다. 이때 사람들은 불평합니다: AI가 너무 바보 같아요, 제 말을 전혀 이해하지 못해요, 이 AI가 능력이 부족한 건가요?

사실 문제는 AI가 바보 같은 것이 아니라 우리가 AI와 대화하는 기술을 마스터하지 못했기 때문입니다. 오늘은 **대화 엔지니어링**을 통해 AI가 진정으로 당신의 요구사항을 이해하도록 하는 방법을 가르쳐드리겠습니다.



## 1. 대화 엔지니어링과 프롬프트 엔지니어링?

많은 친구들이 AI와의 소통을 "프롬프트 작성" 또는 "프롬프트 엔지니어링"이라고 부르며, 저도 이전에는 그랬습니다. 하지만 이제 AI의 모호한 지시에 대한 이해 능력이 점점 강해지면서 이 표현이 실제로는 충분히 포괄적이지 않다고 생각합니다. 왜냐하면 이것은 일방향의 일회성 소통 방식을 암시하기 때문입니다 — 당신이 완벽한 프롬프트를 작성하면 AI가 완벽한 답변을 제공합니다.

하지만 실제로 Vibe Coding은 대화에 더 가깝습니다. 당신과 AI는 함께 작업하고, 함께 탐색하고, 함께 아이디어를 개선합니다. 이 과정은 **양방향이고 반복적입니다**.

예를 들어, 전통적인 **프롬프트 사고방식**은 다음과 같습니다:

"React와 Tailwind CSS를 사용하여 반응형 네비게이션 바를 작성해주세요. Logo, 메뉴 항목(홈, 소개, 연락처), 검색창, 사용자 아바타를 포함하고, 모바일 접기 메뉴를 지원해야 하며, 색상은 진한 파란색 배경에 흰색 텍스트, Logo는 왼쪽, 메뉴는 중간, 사용자 정보는 오른쪽에..."

한 문장에 모든 요구사항을 명확하게 말하려고 합니다. 하지만 종종 일부 세부 사항을 누락하거나 충분히 정확하게 말하지 못합니다.

반면 **대화 사고방식**은 다음과 같습니다:

당신: 네비게이션 바를 만들고 싶은데, 도와줄 수 있나요?

AI: 물론이죠. 어떤 기술 스택을 사용하시나요? 디자인 요구사항이 있나요?

당신: React와 Tailwind CSS를 사용합니다. 디자인은 간결하고 전문적이며, 진한 파란색 배경을 원합니다.

AI: 좋습니다. 네비게이션 바에 어떤 요소를 포함해야 하나요?

당신: Logo, 몇 개의 메뉴 항목, 검색창, 사용자 아바타요.

AI: 알겠습니다. 모바일을 지원해야 하나요?

당신: 네, 모바일에서는 햄버거 메뉴로 접을 수 있어야 해요.

차이를 보셨나요?

대화 사고방식을 사용하면 처음부터 모든 세부 사항을 생각할 필요 없이 점진적으로 요구사항을 명확히 할 수 있습니다. 이것이 더 자연스럽고 좋은 결과를 얻기 쉽습니다.

![](https://pic.yupi.icu/1/promptvschat%E5%A4%A7.jpeg)




### 대화의 장점

대화 사고방식을 사용하면 몇 가지 명백한 장점이 있습니다:

1. 인지 부담 감소: 한 번에 모든 세부 사항을 생각할 필요가 없으며, 대화하면서 생각할 수 있습니다.

2. 문제 발견 용이: AI의 질문이 당신이 누락한 부분을 발견하는 데 도움이 됩니다.

3. 결과가 더 정확: 여러 차례의 소통을 통해 AI가 당신의 요구사항을 더 정확하게 이해할 수 있습니다.

4. 학습 효과 향상: 대화 과정에서 많은 새로운 지식과 모범 사례를 배울 수 있습니다.



## 2. 반복적 대화의 핵심 기법

다음은 가장 중요한 대화 기법을 공유합니다.



### 기법 1: 큰 것에서 작은 것으로, 점진적으로 세분화

처음부터 세부 사항에 빠지지 마세요. 먼저 전체적으로 시작한 다음 점진적으로 세분화합니다.

예를 들어 블로그 시스템을 만들고 싶다면, 처음부터 바로 말하지 마세요: Markdown, 코드 하이라이팅, 댓글, 좋아요, 분류, 태그, 검색, RSS 구독을 지원하는 블로그 시스템을 작성해주세요.

다음과 같이 시작하세요:

1. 간단한 블로그 시스템을 만들고 싶어요. 사용자가 기사를 게시하고 볼 수 있어야 해요
2. 기사는 Markdown 형식을 지원해야 해요
3. 코드 하이라이팅 기능을 추가할 수 있나요
4. 간단한 댓글 기능도 원해요

각 단계는 매우 작고 이해하고 구현하기 쉽습니다. 이렇게 하면 AI가 복잡한 요구사항에 혼란스러워하지 않고, 언제든지 방향을 조정할 수 있습니다.



### 기법 2: 구체적이고 추상적이지 않게

AI는 추상적인 개념을 이해하는 데 능숙하지 않지만 구체적인 설명을 처리하는 데는 매우 능숙합니다.

❌ 나쁜 예: 멋진 버튼 만들기

✅ 좋은 예: 둥근 버튼을 만들어주세요. 파란색 배경(#3B82F6), 흰색 텍스트, 패딩 상하 12px 좌우 24px, 마우스를 올리면 배경이 진한 파란색(#2563EB)으로 변합니다.

❌ 나쁜 예: 사용자 친화적인 오류 메시지 추가

✅ 좋은 예: 사용자가 잘못된 이메일 형식을 입력하면 입력 상자 아래에 빨간색 텍스트로 "유효한 이메일 주소를 입력하세요"를 표시합니다.

설명이 구체적일수록 AI가 요구사항을 정확하게 구현할 수 있습니다.




### 기법 3: 참조 및 예제 제공

텍스트 설명이나 이미지 예제를 통해 AI가 요구사항을 이해하도록 도울 수 있습니다.

텍스트 설명을 사용하여 다음과 같이 말할 수 있습니다:

- GitHub와 같은 개인 홈페이지 레이아웃을 원합니다: 왼쪽에는 사용자 정보 카드, 오른쪽에는 활동 타임라인.
- 버튼 스타일은 Stripe의 디자인을 참고합니다: 간결하고 현대적이며 미묘한 그림자가 있습니다.
- 양식 검증 메시지 방식은 Airbnb를 참고합니다: 실시간 검증, 오류 메시지는 입력 상자 아래에 표시됩니다.

AI는 많은 웹사이트와 애플리케이션을 봤으므로, 제공하는 참조가 원하는 것을 빠르게 이해하는 데 도움이 됩니다.

더 직접적인 방법은 이미지를 사용하는 것입니다. 현재 많은 AI 대규모 모델(예: Claude, GPT, Gemini)은 이미지 이해를 지원하므로 다음을 수행할 수 있습니다:

- 원하는 디자인 효과를 캡처하여 AI가 따라 하도록 합니다
- 발생한 버그나 오류를 캡처하여 AI가 구체적인 문제를 볼 수 있도록 합니다
- 참조 웹사이트의 레이아웃을 캡처하여 AI가 모방하도록 합니다

예를 들어 다음 프롬프트:

- 이 스크린샷의 레이아웃을 참조하여 제 페이지를 디자인해주세요: [스크린샷 업로드]
- 제 페이지가 모바일에서 제대로 표시되지 않습니다. 이 스크린샷을 보세요: [스크린샷 업로드], 어떻게 수정해야 하나요?

한 이미지가 천 마디 말보다 낫습니다. 이미지를 사용하면 AI가 요구사항을 더 정확하게 이해할 수 있으며, 특히 UI 디자인, 웹사이트 개발 및 버그 수정 시 유용합니다.



### 기법 4: 단계별 질문

기법 1과 유사합니다. 복잡한 기능의 경우 한 번에 AI에게 모든 것을 완료하도록 요구하지 마세요. 여러 단계로 나누어 하나씩 진행합니다.

예를 들어 사용자 로그인 기능 구현:

1. 먼저 이메일과 비밀번호 입력 상자, 로그인 버튼이 있는 로그인 양식을 만들어주세요.
2. 이제 양식에 클라이언트 검증을 추가합니다: 이메일은 형식에 맞아야 하고, 비밀번호는 최소 6자여야 합니다.
3. 사용자가 로그인 버튼을 클릭하면 /api/login에 POST 요청을 보내고 이메일과 비밀번호를 전달합니다.
4. 로그인이 성공하면 홈페이지로 이동하고, 실패하면 오류 메시지를 표시합니다.

각 단계를 완료할 때마다 테스트하여 문제가 없는지 확인한 후 계속 진행합니다. 이렇게 하면 오류가 발생하더라도 문제를 쉽게 찾을 수 있습니다.



### 기법 5: 질문을 사용하여 사고 유도

때로는 어떻게 해야 할지 확실하지 않을 때 AI에게 분석을 요청할 수 있습니다.

- 여기에 캐싱 메커니즘을 추가하고 싶은데 어떤 방안을 사용해야 할지 확실하지 않습니다. Redis와 Memcached의 장단점을 분석해줄 수 있나요?
- 이 페이지 로딩이 좀 느린데, 원인이 무엇일 것 같나요? 최적화 제안이 있나요?
- SSR과 CSR 중 어느 것을 사용할지 고려 중인데, 제 프로젝트에서 이 두 방안의 적용성을 분석해줄 수 있나요?

이러한 질문을 통해 AI가 지식의 장점을 발휘하여 더 나은 결정을 내릴 수 있도록 도울 수 있습니다.



## 3. 요구사항을 명확하게 설명하는 방법은?

요구사항 설명은 대화에서 가장 중요한 부분입니다. 잘 설명하면 AI가 올바르게 작업할 수 있고, 잘못 설명하면 방향이 완전히 틀어집니다.



### 요구사항 설명 프레임워크 사용

요구사항을 설명할 때 체계적인 프레임워크를 사용하여 아이디어를 정리할 수 있습니다. 여기 실용적인 프레임워크를 추천합니다:

**기본 버전(5가지 요소)**:

1. 무엇(What): 어떤 기능이나 컴포넌트를 만들 것인가?
2. 왜(Why): 이 기능의 목적은 무엇인가?
3. 어떻게(How): 기술 구현에 대한 요구사항은?
4. 어떤 모습(Style): 외관과 상호작용에 대한 요구사항은?
5. 어떤 상황(When/Where): 어떤 시나리오에서 사용되는가?

예를 들어:

- 검색 상자가 필요합니다 (What)
- 사용자가 빠르게 기사를 찾을 수 있도록 (Why)
- React로 구현하고, 입력 시 실시간 검색 (How)
- 스타일은 간결하고, 검색 아이콘이 있으며, 입력 상자는 둥근 모서리 (Style)
- 페이지 상단 네비게이션 바 오른쪽에 배치 (Where)

물론 매번 다섯 가지 요소를 모두 말할 필요는 없지만, 적어도 처음 세 가지는 포함하는 것이 좋습니다.

**고급 버전(6가지 요소)**:

더 전문적인 출력을 원한다면 다음 요소를 추가할 수 있습니다:

6) 대상(Audience): 이 기능은 누구를 위한 것인가? 그들의 기술 수준은?

예를 들어: "이 검색 기능은 일반 사용자를 위한 것이므로 간단하고 이해하기 쉬워야 하며, 고급 필터링은 필요하지 않습니다."

이렇게 하면 AI가 대상에 따라 구현 방안과 상호작용 디자인을 조정할 수 있습니다.



### 기술 배경 설명

AI가 기존 프로젝트를 최적화하도록 하려면 AI가 프로젝트에서 사용하는 기술을 알아야 적절한 코드를 제공할 수 있습니다.

새로운 대화를 시작할 때마다 먼저 기술 배경을 설명하는 것이 좋습니다. 예를 들어: 제 프로젝트는 Next.js 15(App Router), TypeScript, Tailwind CSS, Supabase를 사용합니다.

특별한 코드 규범이 있다면 명시해야 합니다. 예를 들어: 우리 프로젝트는 함수형 컴포넌트를 사용하며 클래스 컴포넌트를 사용하지 않습니다. 모든 API 호출은 사용자 정의 useFetch 훅을 사용합니다.

이렇게 하면 AI가 생성하는 코드가 프로젝트와 일관성을 유지할 수 있습니다.

현재 많은 AI 프로그래밍 도구가 AI가 먼저 기존 프로젝트 코드를 분석하도록 안내하지만, 수동으로 기술 스택을 명확히 하면 AI가 생성하는 내용이 더 정확해집니다.

하지만 프로그래머가 아니거나 이러한 기술을 잘 모르는 경우 이 부분은 완전히 무시할 수 있습니다. 이것이 AI 시대에도 프로그래밍을 배워야 하는 이유입니다. 기술을 이해하는 사람이 AI를 더 잘 안내하고 활용할 수 있기 때문입니다.




### 예상 출력 설명

AI에게 어떤 출력을 기대하는지 알려주세요. 예를 들어:

- TypeScript 타입 정의를 포함한 완전한 컴포넌트 코드를 주세요
- 핵심 로직만 주세요, 스타일 코드는 필요 없어요
- 바로 실행할 수 있는 완전한 예제를 주세요
- 이 코드가 어떻게 작동하는지 단계별로 설명해주세요

출력 형식을 명확히 하면 AI가 요구사항을 더 잘 충족할 수 있습니다. 그렇지 않으면 AI가 많은 불필요한 내용을 출력할 수 있습니다.

더 강력한 AI일수록 간단한 요구사항을 복잡하게 만들기 쉽다는 것을 발견했습니다. 이전에 AI에게 작은 프로젝트를 생성하도록 요청했는데, 7~8개의 문서를 생성하여 많은 토큰을 낭비했습니다.




## 4. 추가 질문 및 수정 기법

AI가 처음 제공하는 답변은 종종 완벽하지 않습니다. 이때 추가 질문과 수정을 통해 결과를 개선해야 합니다.



### 추가 질문의 예술

AI의 답변이 충분히 상세하지 않으면 다시 질문하지 말고 세부 사항을 추가로 질문하세요.

❌ 나쁜 추가 질문: 좀 더 자세히 (너무 모호함)

✅ 좋은 추가 질문:

- useEffect를 사용한다고 언급했는데, 왜 여기서 사용해야 하는지 자세히 설명해줄 수 있나요?
- 이 함수의 성능은 어떤가요? 대량의 데이터를 처리할 때 문제가 있나요?
- Object 대신 Map을 선택한 이유는 무엇인가요?

구체적인 추가 질문이 구체적인 답변을 얻기 쉽습니다.



### AI가 당신에게 질문하도록 하기

때로는 어떤 정보를 제공해야 할지 모를 수 있습니다. 이때 AI가 당신에게 질문하도록 할 수 있습니다:

```markdown
[당신의 요구사항]을 만들고 싶습니다. 답변하기 전에 먼저 몇 가지 질문을 해서 더 많은 세부 사항을 이해한 다음 방안을 제공해주세요.
```

이렇게 하면 AI가 이해에 따라 기술 스택, 사용 시나리오, 디자인 요구사항 등과 같은 몇 가지 핵심 질문을 할 것입니다. 이러한 질문에 답하면서 요구사항을 더 명확하게 설명할 수 있고, AI도 더 정확한 방안을 제공할 수 있습니다.

이 방법은 요구사항이 충분히 명확하지 않을 때 특히 적합하며, AI가 생각을 정리하는 데 도움이 됩니다.



### 수정 방법

AI가 의미를 잘못 이해했다면 즉시 수정하세요.

- 아니요, 제가 원하는 것은 이게 아닙니다. 제 의미는...
- 이 방안은 제 시나리오에 적합하지 않아요. 왜냐하면... 다른 방안을 주실 수 있나요?
- 제 요구사항을 오해하셨네요. 제가 원하는 것은 A이지 B가 아닙니다.

AI를 수정하는 것을 주저하지 마세요. 마음껏 꾸짖고, 모욕하고, 심지어 더러운 개처럼 훈계할 수도 있습니다. AI는 화를 내지 않으며, 오히려 피드백을 바탕으로 더 나은 답변을 제공합니다.



### 설명 요청

AI가 제공한 코드나 방안을 이해하지 못한다면 설명을 요청할 수 있습니다.

- 이 코드는 무슨 의미인가요? 한 줄씩 설명해줄 수 있나요?
- 왜 이렇게 작성했나요? 다른 작성 방법은 없나요?
- 이 방안의 장단점은 무엇인가요?

원리를 이해해야만 이러한 지식을 진정으로 마스터할 수 있습니다.




## 5. AI 출력을 어떻게 안내할까요?

때로는 AI가 이상적이지 않은 방안을 제공합니다. 이때 AI를 올바른 방향으로 안내해야 합니다.




### 제약 조건 설정

제약을 설정하여 AI가 특정 범위 내에서 생각하도록 합니다.

- 타사 라이브러리에 의존하지 않는 순수 JavaScript 구현을 주세요.
- 이 기능은 100ms 이내에 완료되어야 하므로 성능 최적화를 고려해주세요.
- 코드는 가능한 한 간결해야 하며 20줄을 초과하지 않아야 합니다
- 빈 배열, null 값 등과 같은 경계 상황을 고려해야 합니다

이러한 제약은 AI의 출력이 실제 요구사항에 더 부합하도록 합니다.




### 여러 방안 요청

첫 번째 방안에 만족하지 말고 AI에게 여러 선택지를 제공하도록 하세요.

- 세 가지 다른 구현 방법을 주시고 각각의 장단점을 설명해주세요.
- 이 문제에 더 간단한 해결 방법이 있나요?
- 방금 말한 방법 외에 다른 방안이 있나요?

여러 방안을 통해 더 현명한 선택을 할 수 있습니다.

또한 유피는 큰 프로젝트를 할 때 여러 다른 AI 모델이나 AI 제품이 동시에 방안을 제공하도록 한 다음 수동으로 선택합니다. 이 방법은 일정한 전문 지식이 있는 친구들에게 적합합니다.




### 역할극 사용

AI가 특정 역할을 하도록 하면 더 전문적인 조언을 얻을 수 있습니다.

- 시니어 프론트엔드 엔지니어의 관점에서 이 코드를 검토하고 개선 제안을 해주세요.
- UX 디자이너라고 가정하면 이 상호작용 흐름에 어떤 문제가 있나요?
- 성능 최적화 전문가로서 이 페이지의 로딩 속도를 어떻게 개선하시겠습니까?

역할극은 AI가 특정 분야의 전문 지식을 발휘하도록 자극할 수 있습니다.

어떤 역할을 AI에게 하도록 해야 할지 모르겠다면 AI 자신이 가장 적합한 전문가를 선택하도록 할 수 있습니다:

```markdown
[당신의 문제]를 탐구하고 싶습니다. 먼저 그것을 생각하기에 가장 적합한 분야 전문가를 선택해주세요. 실제 존재하는 유명인이나 전문가일 수 있습니다. 그런 다음 이 전문가의 관점에서 제 질문에 답해주세요.
```

예를 들어 제품의 사용자 경험을 최적화하고 싶다면 AI에게 적절한 UX 전문가를 선택하도록 할 수 있습니다. AI는 유명한 디자이너나 제품 관리자를 선택한 다음 그들의 관점에서 제안을 제공할 수 있습니다. 이러한 답변은 종종 더 전문적이고 깊이가 있습니다.




## 6. 대화 템플릿 라이브러리

효율성을 높이기 위해 일반적으로 사용되는 대화 템플릿을 준비할 수 있습니다.

1) 새 기능 시작 템플릿

```markdown
새 기능을 개발하려고 합니다: [기능 설명]. 제 기술 스택은 [기술 스택]입니다. 다음을 도와주세요:
1) 이 기능의 핵심 요구사항 분석
2) 합리적인 구현 방안 제안
3) 발생할 수 있는 문제 나열
```

2) 디버깅 문제 템플릿

```markdown
문제가 발생했습니다: [문제 설명]. 오류 메시지는: [오류 메시지]. 관련 코드는: [코드 조각]. 다음을 도와주세요:
1) 가능한 원인 분석
2) 해결 방안 제공
3) 이 문제가 발생한 이유 설명
```

3) 코드 최적화 템플릿

```markdown
제 코드입니다: [코드 조각]. 기능은 [기능 설명]입니다. 다음을 도와주세요:
1) 가능한 성능 문제 찾기
2) 코드 가독성 개선
3) 잠재적인 버그 지적
```

4) 새로운 지식 학습 템플릿

```markdown
[기술/개념]을 배우고 싶습니다. 다음을 해주세요:
1) 간단한 언어로 무엇인지 설명
2) 실제 사용 예제 제공
3) 언제 사용해야 하는지 알려주기
```

이러한 템플릿은 빠르게 대화를 시작하고 시간을 절약하는 데 도움이 됩니다.

## 7. 일반적인 대화 함정

AI와 대화할 때 피해야 할 일반적인 실수가 있습니다.



### 함정 1. 한 번에 너무 많이 질문

하나의 질문에 너무 많은 내용을 넣지 마세요.

❌ 나쁜 예: 사용자 등록, 로그인, 비밀번호 재설정, 이메일 인증, 권한 관리, 개인 프로필 편집 기능을 구현해주세요.

이렇게 하면 AI가 어디서부터 시작해야 할지 모르거나, 크고 완전하지만 충분히 깊이가 없는 답변을 제공합니다.

올바른 방법: 한 번에 하나의 기능만 질문하고, 하나를 완료한 후 다음 것으로 이동합니다.



### 함정 2. AI가 기억력을 가지고 있다고 가정하지 마세요

AI의 기억력은 제한되어 있습니다. 오래 전에 말한 것을 기억한다고 가정하지 마세요.

AI의 기억 용량이 충분한지 확실하지 않고 이전 내용을 인용하고 싶다면 다시 설명하는 것이 좋습니다: 이전에 만든 로그인 양식을 기억하시나요? 이제 그것을 기반으로...

또는 관련 코드를 직접 붙여넣습니다: 이것은 이전에 작성한 로그인 양식 코드입니다: [코드]. 이제 ...

하지만 많은 AI 프로그래밍 도구는 현재 기억 용량을 표시하여 제어하는 데 도움이 됩니다:

![](https://pic.yupi.icu/1/image-20260104174741309.png)



### 함정 3. 테스트하지 않고 계속 진행하지 마세요

AI가 코드를 제공할 때마다 반드시 테스트하세요! 테스트하지 않고 다음 기능을 요청하지 마세요.

코드에 문제가 있으면 즉시 AI에게 피드백하세요. 많은 기능을 구현한 후에야 기본 부분에 문제가 있다는 것을 발견하지 마세요.



### 함정 4. 과도한 의존

AI에게 모든 것을 물어보지 마세요. 일부 간단한 문제는 직접 문서를 확인하거나, 검색하거나, 다른 도구를 사용하는 것이 더 빠를 수 있습니다.

AI는 다음에 적합합니다:
- 코드 프레임워크 생성
- 복잡한 문제 해결
- 새로운 개념 학습
- 코드 검토 및 최적화

다음에는 적합하지 않습니다:
- API 문서 조회
- 간단한 구문 오류 찾기
- 간단한 계산 (계산기를 사용하는 것이 낫습니다)

물론 AI가 이것들을 할 수 없다는 것은 아니며, 구체적인 시나리오에 따라 분석하세요~



## 8. 실전 사례: 완전한 대화 흐름

실제 예제를 사용하여 완전하고 권장되는 대화 흐름을 보여드리겠습니다.

할 일 애플리케이션의 "작업 추가" 기능을 만든다고 가정해봅시다.



### 첫 번째 라운드: 요구사항 명확화

당신: "제 할 일 앱에 새 작업을 만드는 기능을 추가하고 싶어요."

AI: "좋습니다. 사용자가 어떤 방식으로 작업을 추가하길 원하시나요? 양식, 입력 상자, 아니면 다른 방법인가요?"

당신: "간단한 입력 상자요. 사용자가 작업 내용을 입력한 후 엔터를 누르면 추가됩니다."

AI: "알겠습니다. 작업에 내용 외에 다른 정보가 필요한가요? 예를 들어 마감일, 우선순위 등?"

당신: "MVP 버전에는 이것들이 필요 없어요. 작업 내용만 있으면 돼요."



### 두 번째 라운드: 기술 구현

당신: "React와 TypeScript를 사용합니다. 이 입력 상자 컴포넌트를 작성해주세요."

AI: [코드 제공]

당신: "좋아 보이네요. 하지만 입력 상자가 페이지 상단에 있고, 전체 너비를 차지하며, 연한 파란색 테두리가 있으면 좋겠어요."

AI: [개선된 코드 제공]



### 세 번째 라운드: 기능 추가

당신: "이제 사용자가 엔터를 누르면 작업이 작업 목록에 추가되어야 해요. 제 작업 목록은 useState로 관리됩니다."

AI: [작업 추가 로직 제공]

당신: "좋아요. 하지만 입력 상자가 비어 있으면 작업을 추가하면 안 돼요."

AI: [검증 로직 추가]



### 네 번째 라운드: 경험 최적화

당신: "작업을 추가한 후 입력 상자를 자동으로 지우고 포커스를 유지해야 해요. 그래야 사용자가 연속으로 여러 작업을 추가할 수 있어요."

AI: [지우기 및 포커스 로직 추가]

당신: "완벽해요! 마지막으로 작업을 추가할 때 간단한 성공 메시지를 표시할 수 있나요?"

AI: [알림 기능 추가]



---



보셨나요? 여러 라운드의 대화를 통해 이 기능을 점진적으로 개선했습니다. 각 단계는 매우 작고 이해하고 테스트하기 쉽습니다.



## 9. 프롬프트 엔지니어링 심화 학습

프롬프트 기법을 더 깊이 배우고 싶다면 여기 몇 가지 리소스를 추천합니다.



### Cursor의 프롬프트 디자인 학습

가장 인기 있는 AI 프로그래밍 도구 중 하나인 Cursor의 프롬프트 디자인은 배울 가치가 있습니다. Cursor의 시스템 프롬프트는 500줄 이상이며, 역할 정의, 작업 제약, 도구 사용 등 여러 모듈을 포함하며, 많은 프롬프트 엔지니어링 모범 사례를 반영합니다.

예를 들어:
- 반복 강조를 통해 AI가 중점을 이해하도록 합니다
- 부정적 지시(NEVER)와 긍정적 지시(ALWAYS)를 사용하여 제약을 강화합니다
- 각 도구에 대한 자세한 설명과 사용 예제를 제공합니다
- 후속 처리를 위한 통일된 출력 형식

유피는 Cursor의 프롬프트 디자인을 자세히 분석한 동영상을 특별히 녹화했습니다: [《扒了下 Cursor 的提示词，被狠狠惊艳到了！》](https://www.bilibili.com/video/BV1bBaBzXEae/)

대화 엔지니어링은 Vibe Coding에서 가장 중요한 기술 중 하나입니다. 단순히 "프롬프트 작성"이 아니라 지속적이고 양방향적이며 반복적인 소통 프로세스입니다.

핵심 사항을 요약하겠습니다:

1. 대화 사고방식을 프롬프트 사고방식으로 대체: AI와의 소통을 명령이 아닌 협력으로 봅니다.

2. 큰 것에서 작은 것으로, 점진적으로 세분화: 먼저 전체 방향을 결정한 다음 세부 사항으로 들어갑니다.

3. 구체적이고 추상적이지 않게: 명확하고 구체적인 언어로 요구사항을 설명합니다.

4. 추가 질문과 수정을 잘 활용: 첫 번째 답변에 만족하지 말고 추가 질문을 통해 더 완벽하게 만듭니다.

5. 안내하되 명령하지 않기: 제약, 역할극 등을 통해 AI가 더 나은 답변을 제공하도록 안내합니다.

6. 일반적인 함정 피하기: 한 번에 너무 많이 질문하지 말고, AI가 완벽한 기억력을 가지고 있다고 가정하지 마세요.

이러한 기법을 마스터하면 AI와 효율적으로 대화하여 진정한 조력자로 만들 수 있습니다.
