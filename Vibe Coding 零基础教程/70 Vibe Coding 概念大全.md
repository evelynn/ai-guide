## AI 기초 개념


### 인공지능 (AI)

인공지능(Artificial Intelligence)은 컴퓨터가 인간의 지능을 모방하도록 하는 기술입니다. 간단히 말해, 기계가 인간처럼 생각하고, 학습하고, 문제를 해결할 수 있게 하는 것입니다.

Vibe Coding에서 AI는 여러분의 프로그래밍 도우미입니다. 무엇을 해야 하는지 알려주면 코드를 작성해줍니다. 24시간 온라인으로 언제든지 도와줄 수 있는 프로그래머 친구가 있는 것과 같습니다.




### 대규모 언어 모델 (LLM)

대규모 언어 모델(Large Language Model)은 인간의 언어를 이해하고 생성할 수 있는 AI 시스템입니다. ChatGPT, Claude, Gemini, DeepSeek는 모두 대규모 언어 모델입니다.

왜 "대규모"라고 할까요? 이러한 모델의 파라미터 수가 매우 방대하기 때문입니다. 수십억에서 수조 개의 파라미터를 가지고 있습니다. 파라미터가 많을수록 모델은 일반적으로 더 똑똑하지만, 더 많은 컴퓨팅 리소스를 소비합니다.

대규모 언어 모델을 엄청난 양의 책과 코드를 읽은 슈퍼 학습자로 이해할 수 있습니다. 수많은 프로그래밍 사례를 본 적이 있어 코드를 작성하고, 코드를 설명하고, 버그를 수정할 수 있습니다.

![](https://pic.yupi.icu/1/1745384872015-f84a47fc-0925-4797-9dfc-e4dfae01a3fa.png)



### 모델 파라미터

파라미터는 모델이 훈련 과정에서 학습한 "지식 포인트"로, 숫자 형태로 모델에 저장됩니다. 파라미터가 많을수록 모델이 기억할 수 있는 지식이 풍부하며, 일반적으로 더 똑똑합니다.

예를 들어:

- GPT-4는 약 1.8조 개의 파라미터를 가지고 있습니다
- Claude 3.5 Sonnet의 파라미터 수는 공개되지 않았지만, 수천억 수준으로 추정됩니다
- DeepSeek-V3는 6,710억 개의 파라미터를 가지고 있습니다

파라미터 수는 모델의 능력과 실행 비용에 영향을 미칩니다. 일반적으로 파라미터가 많을수록 모델이 더 비싸지만 효과도 더 좋습니다.




### 훈련과 추론

훈련(Training)은 AI 모델이 대량의 데이터에서 지식을 학습하는 과정입니다. 이 과정은 엄청난 컴퓨팅 리소스와 시간이 필요하며, 일반적으로 AI 회사에서 완료합니다. 직접 모델을 훈련할 필요는 없습니다.

추론(Inference)은 모델이 학습을 완료한 후 학습한 지식을 사용하여 질문에 답하고 콘텐츠를 생성하는 과정입니다. ChatGPT와 대화할 때 추론을 수행하는 것입니다.

비유하자면: 훈련은 학생이 학교에서 공부하는 것과 같고, 추론은 학생이 시험에 응시하는 것과 같습니다. 우리가 일상적으로 AI 도구를 사용할 때는 모두 추론 능력을 사용하는 것입니다.




### 파인튜닝 (Fine-tuning)

파인튜닝은 기존 모델을 기반으로 특정 도메인의 데이터로 계속 훈련하여 해당 분야에서 모델이 더 나은 성능을 발휘하도록 하는 것입니다.

예를 들어, 대량의 의학 자료로 모델을 파인튜닝하여 의학 전문가로 만들 수 있습니다. 또는 회사의 코드베이스로 파인튜닝하여 프로젝트 스타일을 더 잘 이해하도록 할 수 있습니다.

일반 사용자에게는 파인튜닝 비용이 높으므로 일반적으로 직접 할 필요가 없습니다. 기존 모델을 직접 사용하면 충분합니다.



## Token과 과금


### Token

Token은 AI 모델이 텍스트를 처리하는 기본 단위입니다. "단어 블록"으로 간단히 이해할 수 있습니다.

영어에서 하나의 Token은 대략 하나의 단어 또는 단어의 일부입니다. 중국어에서는 한 글자가 일반적으로 1-2개의 Token입니다.

왜 Token이 중요할까요? AI 서비스는 일반적으로 Token 단위로 요금을 부과하기 때문입니다. 입력한 텍스트와 AI가 출력한 텍스트 모두 Token을 소비합니다. Token을 많이 사용할수록 더 많은 비용이 듭니다.

예를 들어:

- "Hello World"는 약 2개의 Token
- "你好世界"는 약 4-6개의 Token

![](https://pic.yupi.icu/1/image-20260112112612434.png)



### 입력 Token과 출력 Token

AI 서비스는 일반적으로 입력과 출력의 Token을 별도로 계산합니다:

- 입력 Token: AI에게 보내는 내용(프롬프트, 코드, 파일 등)
- 출력 Token: AI가 반환하는 내용(답변, 생성된 코드 등)

일반적으로 출력 Token이 입력 Token보다 더 비쌉니다. 콘텐츠를 생성하는 것이 이해하는 것보다 더 많은 컴퓨팅 파워를 소비하기 때문입니다.

비용 절감 팁: 명확하고 간결한 프롬프트를 작성하여 AI가 한 번에 요구사항을 이해하도록 하고, 반복적인 대화를 줄이세요.



### 컨텍스트 윈도우

컨텍스트 윈도우(Context Window)는 AI 모델이 한 번에 "기억"할 수 있는 최대 콘텐츠 양을 의미하며, Token으로 측정됩니다.

모델마다 컨텍스트 윈도우 크기가 다릅니다:

- GPT-4o: 128K Token (약 10만 중문자)
- Claude 3.5 Sonnet: 200K Token (약 15만 중문자)
- Gemini 2.0 Pro: 2M Token (약 150만 중문자)

컨텍스트 윈도우가 클수록 AI가 처리할 수 있는 코드 양이 많아지고, 기억할 수 있는 대화 기록이 길어집니다. 프로젝트 코드가 많다면 컨텍스트 윈도우가 큰 모델을 선택하는 것이 더 적합합니다.

하지만 컨텍스트 윈도우가 클수록 각 요청마다 소비되는 Token도 많아지고 비용도 높아진다는 점에 유의해야 합니다.



## 프롬프트 관련


### 프롬프트 (Prompt)

프롬프트는 AI에게 주는 지시나 질문입니다. Vibe Coding에서 프롬프트는 자연어로 설명하는 요구사항입니다.

프롬프트의 품질이 AI 출력의 품질을 직접적으로 결정합니다. 좋은 프롬프트는:

- 구체적이고 명확하며 모호하지 않음
- 필요한 배경 정보 포함
- 예상되는 출력 형식 명시

예를 들어, "웹사이트를 만들어주세요"는 모호한 프롬프트이지만, "React로 가계부 웹사이트를 만들어주세요. 지출 추가, 목록 보기, 총액 통계 세 가지 기능을 포함하고, 파란색 톤의 인터페이스로 해주세요"는 좋은 프롬프트입니다.

AI 대화에서 메시지는 일반적으로 세 가지 역할로 구분됩니다:

- 시스템 프롬프트(System): AI의 역할과 행동 규칙을 설정하며, 사용자에게는 보이지 않음
- 사용자 프롬프트(User): 사용자가 AI에게 보내는 메시지
- 어시스턴트 프롬프트(Assistant): AI가 사용자에게 답하는 메시지

이 3가지 역할을 이해하면 대화를 더 잘 구성할 수 있습니다. 예를 들어 디버깅할 때 프롬프트에서 이전 대화 기록을 시뮬레이션하여 AI가 컨텍스트를 더 잘 이해하도록 할 수 있습니다.



### 시스템 프롬프트

시스템 프롬프트(System Prompt)는 대화가 시작되기 전에 설정되는 지시로, AI의 역할, 행동 및 제한을 정의하는 데 사용됩니다.

예를 들어, "당신은 경험이 풍부한 React 개발 전문가입니다. 간결하고 명확한 코드 스타일로 질문에 답해주세요"라고 시스템 프롬프트를 설정할 수 있습니다.

시스템 프롬프트는 전체 대화 과정에서 유효하며, AI 행동을 맞춤화하는 중요한 방법입니다.

![](https://pic.yupi.icu/1/1745462990451-6f2b5727-d47b-436c-9da2-50dac64fb790.png)



### 프롬프트 엔지니어링

프롬프트 엔지니어링(Prompt Engineering)은 프롬프트를 설계하고 최적화하는 기술로, AI가 의도를 더 잘 이해하고 기대에 부합하는 결과를 생성하도록 하는 것이 목적입니다.

이것은 Vibe Coding의 핵심 기술 중 하나입니다. 훌륭한 프롬프트 엔지니어는 더 적은 대화 라운드로 AI가 더 높은 품질의 코드를 생성하도록 할 수 있습니다.



### 제로샷 프롬프트 (Zero-shot)

제로샷 프롬프트는 AI에게 예시를 제공하지 않고 직접 작업을 주는 것입니다.

예를 들어: "이 영어를 중국어로 번역해주세요."

AI는 자신의 훈련 지식을 기반으로 작업을 완료합니다. 간단한 작업의 경우 제로샷 프롬프트만으로 충분합니다.



### 퓨샷 프롬프트 (Few-shot)

퓨샷 프롬프트는 프롬프트에 몇 가지 예시를 제공하여 AI가 원하는 형식이나 스타일을 학습하도록 하는 것입니다.

예를 들어:

```
다음 형식으로 번역해주세요:
영어: Hello → 한국어: 안녕하세요
영어: Thank you → 한국어: 감사합니다
영어: Good morning → 한국어:
```

예시를 제공함으로써 AI가 요구사항을 더 정확하게 이해하고 더 일관된 결과를 출력할 수 있습니다.



### 사고의 연쇄 프롬프트 (Chain-of-Thought)

사고의 연쇄 프롬프트는 AI가 직접 답을 제공하는 대신 단계별로 문제를 생각하도록 하는 것입니다. 복잡한 추론 작업에 특히 효과적입니다.

프롬프트에 "단계별로 생각해주세요" 또는 "Let's think step by step"을 추가하면 AI가 추론 과정을 보여주며, 일반적으로 더 정확한 답을 얻을 수 있습니다.

프로그래밍에서 사고의 연쇄 프롬프트는 AI가 복잡한 요구사항을 더 잘 이해하고 더 합리적인 코드 구조를 생성하도록 도와줍니다.

### Markdown 언어

Markdown은 간단한 기호를 사용하여 형식을 나타내는 경량 텍스트 마크업 언어입니다. 예를 들어 `#`는 제목을, `**텍스트**`는 굵게를, `-`는 목록을 나타냅니다.

Vibe Coding에서 Markdown은 매우 중요합니다:

- AI가 생성하는 답변은 일반적으로 Markdown 형식입니다
- 프로젝트 문서(예: README)는 Markdown으로 작성됩니다
- 규칙 파일도 Markdown 형식입니다

Markdown을 배우면 AI와 더 잘 소통할 수 있고, 더 표준적인 프로젝트 문서를 작성할 수 있습니다.




## AI 프로그래밍 모드


### Vibe Coding

Vibe Coding은 컴퓨터 과학자 Andrej Karpathy가 2025년 2월에 제안한 개념입니다. 자연어와 AI 대화를 통해 AI가 코드를 작성하도록 하고, 사용자는 요구사항 설명, 결과 테스트, 방향 안내만 하면 되는 완전히 새로운 프로그래밍 방식을 설명합니다.

Vibe Coding의 핵심 이념은: 프로그래밍 구문에 능숙할 필요가 없고, 자신의 아이디어를 명확하게 표현할 수 있기만 하면 됩니다. AI가 아이디어를 실행 가능한 코드로 변환합니다.

이것은 배달 음식을 주문하는 것과 같습니다: 배달 플랫폼에 무엇을 먹고 싶은지 말하면 레스토랑이 만들어서 배달해줍니다. 요리할 줄 알 필요는 없지만, 무엇을 먹고 싶은지는 알아야 합니다.



### Agentic Coding 에이전트 프로그래밍

Agentic Coding은 AI가 자율적인 "에이전트"(Agent)처럼 작동하여 작업을 스스로 계획하고, 작업을 실행하고, 결과를 검증할 수 있도록 하는 것으로, 단순히 질문에 수동적으로 답하는 것이 아닙니다.

Cursor의 Agent 모드에서 AI는 다음을 수행할 수 있습니다:

- 여러 파일을 자동으로 읽고 분석
- 구현 방안 계획
- 코드 수정 실행
- 테스트 실행 및 검증
- 문제 자동 수정

이것은 기존의 질의응답 방식의 AI보다 더 강력합니다. 복잡한 다단계 작업을 자율적으로 완료할 수 있기 때문입니다.

![](https://pic.yupi.icu/1/agent-in-cursor.png)



### 다중 에이전트 협업

다중 에이전트 협업(Multi-Agent)은 여러 AI 에이전트가 분업 협력하여 복잡한 작업을 함께 완료하는 것을 의미합니다.

예를 들어, 한 에이전트는 아키텍처 설계를 담당하고, 한 에이전트는 프론트엔드 코드 작성을, 한 에이전트는 백엔드 코드 작성을, 한 에이전트는 코드 리뷰를 담당합니다. 그들은 팀처럼 협력합니다.

최근 2년간 다중 에이전트 시스템은 AI 프로그래밍의 중요한 트렌드가 되고 있으며, 더 복잡한 프로젝트를 처리할 수 있습니다.

![](https://pic.yupi.icu/1/image-20260112112834637.png)



### 에이전트 오케스트레이션

오케스트레이션은 여러 AI 에이전트 또는 AI 작업을 조정하고 관리하여 올바른 순서와 방식으로 작동하도록 보장하는 과정을 의미합니다.

오케스트라 지휘자처럼, 오케스트레이터는 어떤 에이전트가 언제 무엇을 할지, 정보를 어떻게 전달할지, 결과를 어떻게 집계할지 결정합니다.

![](https://pic.yupi.icu/1/image-20260112112854174.png)



### Agent Loop 에이전트 루프

Agent Loop는 AI 에이전트의 핵심 작업 메커니즘으로, 에이전트가 작업을 완료하기 위해 지속적으로 실행되는 방법을 설명합니다.

일반적인 Agent Loop에는 다음이 포함됩니다:

1. 감지: 현재 환경 정보 획득(파일 읽기, 오류 확인 등)
2. 사고: 상황 분석, 다음 행동 결정
3. 행동: 구체적인 작업 실행(코드 작성, 명령 실행 등)
4. 관찰: 행동 결과 확인
5. 루프: 결과에 따라 계속할지 결정

이 루프는 작업이 완료되거나 종료 조건에 도달할 때까지 계속됩니다. Agent Loop를 이해하면 Cursor Agent와 같은 도구를 더 잘 사용할 수 있습니다.



### ReAct 추론과 행동

ReAct(Reasoning and Acting)는 AI 에이전트가 추론과 행동을 번갈아 가며 수행하도록 하는 기술 프레임워크입니다.

기존 AI는 생각만 하고 행동하지 않거나, 행동만 하고 생각하지 않았습니다. ReAct는 AI가 다음을 수행할 수 있도록 합니다:

- 먼저 추론: 현재 상황을 생각하고 계획 수립
- 다음 행동: 구체적인 작업 실행
- 결과 관찰: 행동 효과 확인
- 계속 추론: 결과에 따라 전략 조정

이러한 "사고 - 행동 - 관찰" 루프를 통해 AI가 복잡한 작업을 더 안정적으로 완료할 수 있으며, 현대 AI 프로그래밍 도구의 핵심 기술 중 하나입니다.

![](https://pic.yupi.icu/1/react-agent.png)



### 도구 호출

도구 호출(Tool Use / Function Calling)은 AI가 외부 도구와 기능을 사용할 수 있도록 하는 기술입니다. AI 자체는 텍스트만 생성할 수 있지만, 도구 호출을 통해 다음을 수행할 수 있습니다:

- 파일 읽기 및 쓰기
- 명령줄 명령 실행
- 웹 검색
- API 호출
- 데이터베이스 조작

![](https://pic.yupi.icu/1/1746590338968-0240c12b-2956-47f4-b8ff-5b5f831221f6.png)

Vibe Coding에서 도구 호출은 AI를 "말만 하는 것"에서 "손으로 할 수 있는 것"으로 변화시킵니다. 예를 들어 Cursor의 Agent 모드는 도구 호출을 통해 코드 파일을 수정합니다.



### Agent Skills 에이전트 스킬

Agent Skills(에이전트 스킬)는 Anthropic이 2025년 10월에 출시한 개방형 표준으로, AI 에이전트에 특정 도메인의 전문 능력을 확장하는 데 사용됩니다.

간단히 말해, Skill은 `SKILL.md` 파일이 포함된 폴더로, 지시 설명, 스크립트 코드, 참고 자료 등을 배치할 수 있습니다. AI가 관련 작업을 만나면 해당 Skill을 자동으로 로드하여 자신의 능력을 향상시킵니다.

![](https://pic.yupi.icu/1/agent%2520skills.jpeg)

Skill을 AI를 위한 "신입 직원 온보딩 가이드"로 이해할 수 있습니다. 예를 들어:

- PDF 처리 Skill, AI에게 PDF 양식을 작성하는 방법을 가르침
- 프로젝트 배포 Skill, 팀 고유의 배포 프로세스 및 스크립트 포함
- 코드 리뷰 Skill, 프로젝트의 코드 규범 및 체크리스트 정의

Skills의 핵심 설계는 **점진적 공개**입니다: AI는 필요할 때만 관련 콘텐츠를 로드하며, 모든 정보를 한 번에 컨텍스트에 넣지 않아 Token을 절약하면서 유연성을 유지합니다.

![](https://pic.yupi.icu/1/agent%20skills%20bundling.jpeg)



### A2A (Agent-to-Agent)

A2A(Agent-to-Agent)는 AI 에이전트 간의 상호 통신 및 협업 프로토콜 또는 방식을 의미하며, 다중 에이전트 시스템의 기초 기술입니다.

사람과 사람 사이에 언어가 필요한 것처럼, AI 에이전트 간에도 정보를 교환하고, 작업을 분배하고, 결과를 보고하기 위한 표준화된 방법이 필요합니다.

A2A 프로토콜은 다양한 AI 에이전트가 팀을 구성하여 분업 협력으로 복잡한 작업을 완료할 수 있도록 합니다.

![](https://pic.yupi.icu/1/a2a-agent.png)



## 컨텍스트 관리


### 컨텍스트 (Context)

컨텍스트는 AI가 질문에 답할 때 참조할 수 있는 모든 정보를 말하며, 다음을 포함합니다:

- 현재 대화의 기록
- 열어 놓은 코드 파일
- 프로젝트의 구조와 설정
- 제공한 참고 자료

컨텍스트가 풍부하고 관련성이 높을수록 AI가 생성하는 코드가 요구사항에 더 부합합니다. 이는 신입 동료에게 업무를 인수인계하는 것과 같습니다 — 배경 정보를 많이 제공할수록 더 빨리 적응합니다.



### 컨텍스트 엔지니어링

컨텍스트 엔지니어링(Context Engineering)은 AI에 제공하는 컨텍스트 정보를 전략적으로 관리하고 최적화하는 기술입니다.

핵심 목표는 **AI가 적절한 정보를 갖도록 하는 것**입니다. 너무 적으면(AI가 상황을 이해하지 못함) 안 되고, 너무 많으면(정보 과부하, 비용 증가) 안 됩니다.

좋은 컨텍스트 엔지니어링에는 다음이 포함됩니다:

- 가장 관련성 높은 파일 선택
- 필요한 배경 설명 제공
- 규칙 파일을 사용하여 프로젝트 규범 정의
- 적시에 무관한 대화 기록 정리



### 규칙 파일

규칙 파일(Rules File)은 프로젝트 루트 디렉토리에 배치된 설정 파일로, AI에게 프로젝트 규범, 기술 스택, 코드 스타일 등의 정보를 알려주는 데 사용됩니다.

Cursor에서는 이 파일을 `.cursorrules`라고 하고, Claude Code에서는 `CLAUDE.md`라고 합니다. (참고: 도구 버전이 업데이트되면서 이러한 파일의 이름과 표준이 변경될 수 있습니다)

규칙 파일이 있으면 AI가 코드를 생성할 때마다 이러한 규칙을 참조하여 프로젝트 스타일에 더 부합하는 코드를 생성하며, 반복적으로 강조하는 번거로움을 덜어줍니다.



### RAG 검색 증강 생성

RAG(Retrieval-Augmented Generation)는 AI가 외부 지식 베이스를 조회할 수 있도록 하는 기술입니다.

일반 AI는 훈련 시 학습한 지식에만 의존하지만, RAG는 AI가 질문에 답할 때 먼저 문서, 코드베이스, 지식 베이스에서 관련 정보를 검색한 다음 이러한 정보를 기반으로 답변을 생성하도록 합니다.

이는 Vibe Coding에 특히 유용합니다. AI가 프로젝트의 기존 코드를 참조하여 스타일이 일관된 새 코드를 생성할 수 있기 때문입니다.

![](https://pic.yupi.icu/1/1745810809620-15c36bc0-5130-47fc-aaca-7d2a6ce6e3ce.png)




### 벡터 데이터베이스

벡터 데이터베이스는 "벡터"(숫자 표현 형식)를 저장하고 쿼리하는 데 특화된 데이터베이스입니다. AI 분야에서는 텍스트의 의미 표현을 저장하는 데 자주 사용됩니다.

코드나 문서를 벡터 데이터베이스에 저장하면 AI가 검색어와 원문이 완전히 일치하지 않더라도 의미적으로 유사한 콘텐츠를 빠르게 찾을 수 있습니다.

예를 들어 "사용자 로그인"을 검색하면 "handleAuth"라는 함수를 찾을 수 있습니다. 의미적으로 관련이 있기 때문입니다.

![](https://pic.yupi.icu/1/1745813546910-9b39355a-85ab-4673-b52b-7f11349a55d7.jpeg)




### 임베딩 Embedding

임베딩은 텍스트, 코드 등의 콘텐츠를 숫자 벡터로 변환하는 과정입니다. 이러한 벡터는 콘텐츠의 의미 정보를 캡처할 수 있습니다.

벡터 공간에서 의미적으로 유사한 콘텐츠는 더 가까이 위치합니다. 이것이 벡터 데이터베이스가 의미 검색을 수행할 수 있는 원리입니다.

임베딩의 기술적 세부 사항을 깊이 이해할 필요는 없으며, RAG 및 코드 의미 검색의 기초 기술이라는 것만 알면 됩니다.

![](https://pic.yupi.icu/1/1745812543781-8ef377d0-2dac-4d17-a504-35de13fbaad0.png)




### MCP 모델 컨텍스트 프로토콜

MCP(Model Context Protocol)는 Anthropic이 2024년 말에 출시한 개방형 표준으로, AI 모델이 외부 데이터 소스 및 도구에 안전하게 연결할 수 있도록 하는 데 사용됩니다.

MCP를 AI 세계의 "USB 인터페이스"로 이해할 수 있습니다. MCP가 있으면 AI가 파일을 읽고, 데이터베이스에 접근하고, 다양한 도구를 호출할 수 있으며, 각 도구마다 별도의 인터페이스를 개발할 필요가 없습니다.

![](https://pic.yupi.icu/1/1746710765234-c974bda8-666e-45b3-adc4-ace97cbb8c0a.png)

Vibe Coding에서 MCP는 AI가 프로젝트 컨텍스트를 더 편리하게 얻을 수 있도록 하여 코드 생성의 정확성을 높입니다.

![](https://pic.yupi.icu/1/1746677838632-9278e62b-c850-4d3c-a835-297ccbe2061a.png)



## AI 출력 관련


### AI 환각

AI 환각(Hallucination)은 AI가 존재하지 않는 콘텐츠를 만들어내는 것을 의미합니다. 예: 가상의 API, 잘못된 함수 사용법, 존재하지 않는 라이브러리.

이것은 대규모 언어 모델의 고유한 문제입니다. 확률을 기반으로 콘텐츠를 생성하기 때문에 때때로 존재하지 않는 것을 "상상"합니다.

환각을 만났을 때의 대응 방법:

- AI에게 문서 링크를 제공하도록 요청하여 확인
- 직접 공식 문서를 확인
- 다른 모델을 시도
- 새 대화를 열고 문제를 다시 설명




### 온도

온도(Temperature)는 AI 출력의 무작위성을 제어하는 매개변수로, 일반적으로 0-2 사이의 값을 갖습니다.

- 온도가 낮음(예: 0.1): 출력이 더 확실하고 보수적이며 코드 작성에 적합
- 온도가 높음(예: 1.0): 출력이 더 무작위적이고 창의적이며 브레인스토밍에 적합

프로그래밍 시나리오에서는 일반적으로 더 낮은 온도를 사용하여 AI가 더 안정적이고 예측 가능한 코드를 생성하도록 합니다.




### 스트리밍 출력

스트리밍 출력(Streaming)은 AI가 콘텐츠를 생성하면서 실시간으로 표시하는 것을 의미하며, 모두 생성될 때까지 기다린 후 표시하는 것이 아닙니다.

이것은 녹화 방송이 아닌 생방송을 보는 것과 같습니다. AI의 사고 과정을 실시간으로 볼 수 있으며, 방향이 잘못되었다고 판단되면 즉시 중단할 수 있습니다.

대부분의 AI 프로그래밍 도구는 스트리밍 출력을 지원하여 상호 작용 경험을 더 부드럽게 만듭니다.



## 개발 도구 개념


### IDE 통합 개발 환경

IDE(Integrated Development Environment)는 프로그래머가 코드를 작성하는 데 사용하는 종합 소프트웨어로, 일반적으로 코드 에디터, 디버거, 터미널 등의 도구를 포함합니다.

VS Code는 현재 가장 인기 있는 IDE입니다. Cursor와 Windsurf는 모두 VS Code를 기반으로 개발된 AI 코드 에디터로, VS Code의 기능을 계승하면서 AI 기능을 추가했습니다.

![](https://pic.yupi.icu/1/image-20260112113710320.png)




### 코드 에디터

코드 에디터는 코드를 작성하고 수정하는 데 사용되는 도구입니다. 일반적으로 구문 강조, 코드 완성, 오류 알림 등의 기능을 제공하여 더 효율적으로 코드를 작성할 수 있도록 도와줍니다.

일반적인 코드 에디터로는 Sublime Text 등이 있습니다. IDE와의 차이점은 상대적으로 가볍고 빠르게 시작되며 단일 파일을 빠르게 편집하는 데 적합하다는 것입니다. 반면 IDE는 더 포괄적인 기능을 제공하며 디버거, 터미널, 버전 제어 등의 도구를 통합하여 대규모 프로젝트 개발에 적합합니다.

Vibe Coding 시대에 코드 에디터는 AI 기능을 통합하여 프롬프트에 따라 코드를 자동으로 생성하고, 코드를 설명하고, 오류를 수정할 수 있습니다. 예를 들어 Cursor는 IDE처럼 강력한 기능을 가지고 있지만 핵심은 여전히 AI 강화 코드 에디터입니다.




### 노코드 플랫폼

노코드 플랫폼(No-Code Platform)은 코드를 작성하지 않고도 애플리케이션을 만들 수 있는 플랫폼입니다. 시각적 인터페이스를 통해 컴포넌트를 드래그하고 매개변수를 구성하여 애플리케이션을 구축합니다.

AI 시대에 Bolt.new, Lovable, v0.dev, 百度秒哒와 같은 플랫폼은 노코드와 AI를 결합했습니다. 자연어로 요구사항을 설명하면 플랫폼이 완전한 애플리케이션을 자동으로 생성합니다.

노코드 플랫폼은 프로그래밍 경험이 전혀 없는 초보자나 빠르게 프로토타입을 만들고 싶은 경우에 특히 적합합니다.

![](https://pic.yupi.icu/1/image-20260104141512389.png)




### 코드 완성

코드 완성(Code Completion)은 AI가 다음에 작성할 코드를 예측하고 자동으로 제안을 제공하는 기능입니다.

코드를 작성할 때 AI가 컨텍스트를 기반으로 의도를 추측하고 선택할 수 있는 코드 스니펫을 제공합니다. Tab 키를 누르면 제안을 수락할 수 있으며, 코딩 속도가 크게 향상됩니다.

GitHub Copilot은 현재 가장 잘 알려진 AI 코드 완성 도구입니다.




### 코드 리뷰

코드 리뷰(Code Review)는 코드 품질을 확인하고, 문제를 발견하고, 개선 제안을 제시하는 과정입니다.

기존 개발에서는 일반적으로 동료나 상급자가 수행합니다. Vibe Coding에서는 AI에게 코드를 리뷰하도록 요청할 수 있으며, AI는 잠재적인 버그, 보안 문제, 성능 문제를 지적하고 수정 제안을 제공합니다.

![](https://pic.yupi.icu/1/image-20260112114023226.png)

하지만 AI의 리뷰가 수동 리뷰를 완전히 대체할 수는 없으며, 특히 중요한 프로덕션 코드의 경우 주의해야 합니다.




### Linter 코드 검사기

Linter는 코드 문제를 자동으로 검사하는 도구로, 구문 오류, 스타일 문제, 잠재적 버그 등을 발견할 수 있습니다.

일반적인 Linter로는 ESLint(JavaScript), Pylint(Python) 등이 있으며, 엄격한 문법 교사처럼 코드 규범을 유지하도록 도와줍니다.

Vibe Coding에서 Linter는 AI가 생성한 코드의 문제를 빠르게 발견하는 데 도움이 됩니다.




### 디버깅

디버깅(Debug)은 코드의 오류를 찾아 수정하는 과정입니다. 코드 실행 결과가 예상과 다를 때 디버깅을 통해 문제를 찾아야 합니다.

일반적인 디버깅 방법:

- 중단점 설정, 코드 단계별 실행
- 변수 값 확인
- 오류 메시지 및 스택 추적 읽기
- 로그 출력 추가

![](https://pic.yupi.icu/1/image-20251027214825243.png)

Vibe Coding에서는 오류 정보를 AI에게 보내 원인을 분석하고 수정 방안을 제공하도록 요청할 수 있습니다.



## 프로젝트 관리 개념


### MVP (최소 실행 가능 제품)

MVP(Minimum Viable Product)는 최소한의 기능으로 핵심 요구사항을 충족하는 제품 버전입니다.

MVP의 장점:

- 아이디어의 타당성을 빠르게 검증
- 불필요한 기능에 시간을 낭비하지 않음
- 사용자 피드백을 더 빠르게 얻음

예를 들어 가계부 애플리케이션을 만들 때 MVP 버전에는 지출 기록, 목록 보기 두 가지 기능만 있고, 다른 고급 기능은 나중에 추가합니다.



### 반복 개발

반복 개발은 대규모 프로젝트를 여러 개의 작은 주기로 나누어 각 주기마다 일부 기능을 완성하는 개발 방법입니다.

각 반복 주기에는: 계획 => 개발 => 테스트 => 출시 => 피드백 => 개선이 포함됩니다.

이 방법은 Vibe Coding에 특히 적합합니다. AI가 먼저 핵심 기능을 구현하고, 테스트에 문제가 없으면 점진적으로 새 기능을 추가할 수 있기 때문입니다.



### 리팩토링

리팩토링(Refactoring)은 기능을 변경하지 않으면서 코드 구조와 품질을 개선하는 과정입니다.

리팩토링의 목적은 코드를 더 명확하고, 유지 관리하기 쉽고, 효율적으로 만드는 것입니다. 일반적인 리팩토링:

- 반복 코드를 함수로 추출
- 변수 및 함수 이름 개선
- 복잡한 로직 단순화
- 너무 긴 파일 분할

Vibe Coding에서 AI에게 코드를 리팩토링하도록 요청할 수 있지만, 작은 단계로 진행하고 각 리팩토링 후 테스트해야 합니다.



### 기술 부채

기술 부채(Technical Debt)는 기능을 빠르게 완성하기 위해 채택한 임시 방안으로, 미래에 시간을 들여 수정하고 개선해야 하는 것들입니다.

신용카드 빚과 같습니다. 지금은 편리하게 사용할 수 있지만 나중에 갚아야 하고, 이자도 붙습니다.

Vibe Coding에서 AI가 생성한 코드가 최적의 솔루션이 아닐 수 있으며, 기술 부채가 너무 많이 쌓이면 프로젝트 유지 관리가 점점 어려워집니다. 정기적인 리팩토링은 기술 부채를 갚는 방법이며, 레거시 코드가 되는 것을 방지합니다.

![](https://pic.yupi.icu/1/v2-806707f0f72072f1db481c237fc035ea_1440w-20260112114757928.png)



### 버전 제어

버전 제어는 코드 변경 기록을 기록하는 시스템으로, 각 수정을 추적하고, 다른 버전을 비교하고, 이전 상태로 되돌릴 수 있습니다.

Git은 가장 인기 있는 버전 제어 도구이고, GitHub는 가장 인기 있는 코드 호스팅 플랫폼입니다.

Vibe Coding에서 버전 제어는 특히 중요합니다. AI가 문제가 있는 코드를 생성할 수 있기 때문에, 버전 제어가 있으면 언제든지 이전의 정상 버전으로 되돌릴 수 있습니다.

![](https://pic.yupi.icu/1/image-20260112114940228.png)




### 배포

배포(Deployment)는 개발된 애플리케이션을 서버에 게시하여 사용자가 접근하고 사용할 수 있도록 하는 과정입니다.

일반적으로 사용되는 배포 플랫폼:

- Vercel: 프론트엔드 및 풀스택 애플리케이션에 적합
- Netlify: 정적 웹사이트 및 프론트엔드 애플리케이션에 적합
- Railway, Render: 백엔드 서비스에 적합

많은 노코드 플랫폼(예: Bolt.new)은 원클릭 배포를 지원하여 버튼 클릭만으로 온라인에 게시할 수 있습니다.



## 프론트엔드/백엔드 개념


### 프론트엔드

프론트엔드(Frontend)는 사용자가 직접 보고 상호 작용할 수 있는 부분으로, 웹 페이지 인터페이스, 버튼, 폼, 애니메이션 등을 포함합니다.

프론트엔드 기술 스택에는 일반적으로 다음이 포함됩니다:

- HTML: 페이지 구조
- CSS: 스타일 및 레이아웃
- JavaScript: 상호 작용 로직
- React/Vue/Next.js: 현대적인 프론트엔드 프레임워크

Vibe Coding에서 프론트엔드는 AI가 가장 잘 생성하는 부분입니다. 효과를 직접 볼 수 있어 검증과 조정이 용이하기 때문입니다.




### 백엔드

백엔드(Backend)는 사용자가 볼 수 없는 부분으로, 비즈니스 로직 처리, 데이터 저장, 사용자 인증 등을 담당합니다.

백엔드 기술 스택에는 일반적으로 다음이 포함됩니다:

- Node.js/Python/Java: 프로그래밍 언어
- Express/FastAPI/Spring: Web 프레임워크
- MySQL/PostgreSQL/MongoDB: 데이터베이스

백엔드는 프론트엔드보다 더 복잡하며 보안, 성능, 데이터 일관성 등을 고려해야 합니다. AI가 생성한 백엔드 코드는 더 신중하게 검토해야 합니다.




### 풀스택

풀스택(Full-stack)은 프론트엔드와 백엔드를 모두 포함하는 완전한 애플리케이션을 의미합니다. 풀스택 개발자는 프론트엔드와 백엔드 작업을 모두 처리할 수 있는 프로그래머입니다.

Vibe Coding에서 Bolt.new와 같은 도구는 풀스택 애플리케이션을 한 번에 생성할 수 있으며, 프론트엔드와 백엔드 코드를 모두 작성해줍니다.

풀스택 프로그래머가 무엇인지, 어떻게 되는지 더 자세히 알고 싶다면 鱼皮의 이 글을 참조하세요: [전체 스택 프로그래머란?](https://www.bilibili.com/opus/534338036646820466)




### API

API(Application Programming Interface)는 다른 프로그램 간의 통신 인터페이스입니다.

API를 레스토랑 메뉴로 이해할 수 있습니다. 메뉴는 어떤 요리를 주문할 수 있는지, 어떻게 주문하는지, 주문 후 무엇을 받을지 알려줍니다. 주방에서 요리를 어떻게 만드는지 알 필요 없이 메뉴에 따라 주문하기만 하면 됩니다.

웹 개발에서 프론트엔드는 API를 통해 백엔드와 통신하여 데이터를 가져오거나 작업을 제출합니다.

API 인터페이스와 표준 API 인터페이스 설계 규범에 대해 더 자세히 알고 싶다면 [鱼皮의 API 애니메이션 가이드 비디오](https://www.bilibili.com/video/BV1WFBXBmExs)를 시청하세요.




### 데이터베이스

데이터베이스는 데이터를 저장하고 관리하는 시스템입니다. 애플리케이션의 사용자 정보, 콘텐츠, 설정 등이 모두 데이터베이스에 저장됩니다.

일반적인 데이터베이스 유형:

- 관계형 데이터베이스(MySQL, PostgreSQL): 데이터가 테이블 형식으로 저장됨
- 문서 데이터베이스(MongoDB): 데이터가 JSON 문서 형식으로 저장됨
- 키-값 데이터베이스(Redis): 캐싱 및 빠른 조회에 적합

Vibe Coding에서 Supabase, Firebase 등의 BaaS 서비스를 사용하면 직접 데이터베이스를 구축하고 관리할 필요가 없습니다.

### BaaS (Backend as a Service)

BaaS(Backend as a Service)는 데이터베이스, 사용자 인증, 파일 저장 등 기성 백엔드 기능을 제공하는 클라우드 서비스입니다.

일반적으로 사용되는 BaaS 서비스:

- Supabase: 오픈소스 Firebase 대안
- Firebase: Google의 BaaS 플랫폼
- PlanetScale: 호스팅 MySQL 서비스

BaaS를 사용하면 직접 백엔드 코드를 작성하거나 서버를 관리할 필요가 없어 개발 속도를 크게 높일 수 있습니다. Vibe Coding 시나리오에 특히 적합합니다.
